# 2048

命令行版 2048 自动对弈，按职责分层拆分自原先的单文件 `2048.py`（141 行、一个类包办全部）。

## 快速开始

```bash
python main.py                                  # 默认 greedy 策略 + 终端动画
python main.py -s fixed                         # 复现拆分前的行为
python main.py -s expectimax --depth 3          # 更强的搜索策略（更深）
python main.py -s expectimax --profile strong    # 研究增强评估 + 自适应深度（推荐）
python main.py -s expectimax --profile strong --depth 3  # 想更强可叠固定深搜（更慢）
python main.py -s mcts --iterations 100          # 蒙特卡洛树搜索（另一种思路）
python main.py -q --no-wait --seed 42 -s greedy # 静默跑一局，可复现
python main.py --compare -g 12 --seed 2026      # 相同牌运下横向对比全部策略
python main.py -h                               # 全部参数
```

零第三方依赖，Python >= 3.10。

跑测试：

```bash
python -m unittest discover -s tests -t .
```

## 架构

依赖方向严格自上而下，不存在反向依赖，也没有环：

```
        cli.py            参数解析、装配、进程退出码
          |
          v
        app/              编排：runner 驱动循环，benchmark 批量跑分
        /   \
       v     v
 strategy/   render/      决策器             呈现器
       \     /
        v   v
        core/             Board / Direction / rules / Game / result
```

| 层 | 目录 | 职责 | 硬约束 |
| --- | --- | --- | --- |
| 领域核心 | `game2048/core/` | 棋盘、方向、规则、对局状态、结果 DTO | 不 import 上层；不做任何 I/O；`rules` 全是纯函数 |
| 决策 | `game2048/strategy/` | 选下一步往哪走 | 只读棋盘，禁止修改；不做 I/O |
| 呈现 | `game2048/render/` | 把快照显示出去 | 只读快照，不参与决策 |
| 编排 | `game2048/app/` | 装配三者并驱动循环 | 不实现规则，不实现渲染 |
| 入口 | `game2048/cli.py`、`main.py` | 参数解析与装配 | 不含业务逻辑 |

### 三个关键设计决定

**1. `Board` 是不可变值对象。**
原实现的 `move()` 就地修改 `self.board` 并顺手生成新方块，导致"先假设走这一步、看看结果"根本没法做——一模拟就把真实棋局毁了，所以原来只能写死板的固定顺序。改成 frozen 之后，规则函数一律返回新棋盘，策略层可以自由做任意深度的前瞻搜索，`expectimax` 才成为可能。附带好处：棋盘可哈希，"这一步有没有改变棋面"退化成一次 `==`。

**2. 四个方向归一化到一份规则。**
原 `move()` 里"左/右"和"上/下"各写了一遍压缩-合并-补零，约 50 行重复代码。现在任何方向都先把棋盘变换成"向左移动"的等价形态（转置 / 镜像），只调用唯一的 `slide_line()`，再逆变换回去。重复逻辑从 4 份收敛到 1 份。

**3. 随机性显式注入。**
原来直接用模块级 `random`，同一局棋永远无法复现。现在 `Game(rng=...)` / `Game(seed=...)` 注入随机源，同种子结果完全一致——这是"在相同牌运下比较不同策略"的前提。

## 策略

| 名称 | 说明 |
| --- | --- |
| `fixed` | 按 右→下→左→上 固定顺序尝试（拆分前的行为，作为基线） |
| `random` | 合法方向中等概率随机（下限参照） |
| `greedy` | 一步前瞻 + 启发式评估 |
| `expectimax` | 多步 Expectimax，Max 节点选方向、Chance 节点对新方块求期望；`--profile strong` 时自动用**自适应深度**（越空搜越浅、越满搜越深，见下文） |
| `mcts` | 蒙特卡洛树搜索：每次选择都跑大量随机模拟、用 UCB1 估计每个走法的期望价值。与 Expectimax 思路互补——前者对随机落子**穷举求精确期望**，后者**采样估计期望** |

评估函数在 `strategy/heuristics.py`，线性加权五个维度：空格数、单调性、平滑度、最大块角落锚定、**合并潜力**。权重集中在 `DEFAULT_WEIGHTS` / `STRONG_WEIGHTS` 两个预设里，`--profile strong` 切换（详见「算法设计依据」一节）。

实测（全部同种子同牌运：`seed=2026`，单局上限 2000 步；样本较小仅示意量级）。

**算法对比（默认权重；expectimax 固定深度 2；mcts 每步 25 轮模拟）**

| 策略 | 局数 | 平均分 | 中位分 | 最高分 | 平均步 | 最大块 | 达 2048 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| expectimax | 4 | 28396.0 | 25984.0 | 45636 | 1439.8 | 4096 | 50% |
| mcts | 4 | 7413.0 | 8480.0 | 11352 | 463.8 | 1024 | 0% |
| greedy | 4 | 6653.0 | 6314.0 | 12264 | 445.0 | 1024 | 0% |
| fixed | 4 | 2326.0 | 2198.0 | 3224 | 212.5 | 256 | 0% |
| random | 4 | 1109.0 | 1210.0 | 1408 | 120.0 | 128 | 0% |

MCTS 在每步仅 25 轮模拟下已超过 greedy，且**强度随 `--iterations` 提升而提升**（纯 Python 下每步更慢——它是「用时间换强度」的旋钮，与 Expectimax 的「用深度换强度」互补）。

**`--profile strong`（研究增强评估）下：自适应深度 vs 固定深度 2（同权重，隔离深度策略的影响）**

| 配置 | 局数 | 平均分 | 中位分 | 最高分 | 平均步 | 最大块 | 达 2048 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| expectimax · strong · 自适应深度(cap=3) | 4 | 38221.0 | 36256.0 | 45780 | 1889.5 | 4096 | 100% |
| expectimax · strong · 固定深度 2 | 4 | 35294.0 | 39376.0 | 46232 | 1658.2 | 4096 | 75% |

同样的研究增强评估函数下，自适应深度（越空越浅、越满越深）把平均分从 35294 提到 38221、达 2048 比例从 75% 升到 100%，且早期更浅的搜索让它更快——这正是 `--profile strong` 默认开启它的原因。想再强可叠加 `--depth` 固定深搜（更慢），或给 MCTS 加大 `--iterations`。

### 自适应深度调度

`adaptive_depth(空格数, cap)` 的映射（`--profile strong` 默认 `cap=3`）：

| 空格数 | 搜索深度 |
| --- | --- |
| ≥ 6（早期） | 1 |
| 4–5 | 2 |
| 2–3 | 3 |
| ≤ 1（终局） | `min(4, cap)` |

即早期只搜 1 层（chance 节点分支爆炸、且单步影响小），终局自动加深（分支受限、每步都关键）。`--max-depth` 抬高上限；一旦显式指定 `--depth` 就退回固定深搜、关闭自适应。

## 算法设计依据（联网调研）

拆分之后的策略层做增强时，先联网核对了 2048 AI 的共识做法（2026-08），要点沉淀如下，供后续调参参考：

- **为什么是 Expectimax 而不是 Minimax**：2048 的「对手」是随机落子，不是想打败你的对手。Minimax 假设对方走最优，Expectimax 对随机分支求期望，才是对的模型。`core` 改成不可变棋盘后，任意深度的前瞻搜索才成立。
- **概率模型用 90% / 10%**：实际规则是新方块 90% 是 2、10% 是 4。有些开源实现偷懒用 50/50，会在后期高估风险；本项目用真实概率（`_SPAWN_CANDIDATES`）。
- **评估函数的关键维度**（线性加权）：
  1. 空格数——灵活性，权重最高；
  2. 单调性——数值沿行/列单调（「蛇形」被普遍视为黄金法则）；
  3. 平滑度——相邻块数值接近才容易合并；
  4. 最大块角落锚定——把大块锁在角上避免被困；
  5. **合并潜力**——相邻且相等、下一步就能合并的方块对越多越好。这是初版缺失、本次联网调研后补上的维度（J4NN0/2048-ai 等多个强实现都把它列为关键特征）。
- **搜索深度的权衡**：深度越大越强，但复杂度指数爆炸。voldikss/EE369-2048-AI 默认深度 4。`--profile strong` 现在开启**自适应深度**——早期空格多、chance 节点分支爆炸且单步影响小，只搜 1~2 层；终局空格少、每步都关键且分支受限，自动加到 3 层（上限 `--max-depth`）。这样用「浅搜早期 + 深搜终局」替代「全程固定深度」，既提速又增强，详见「自适应深度」一节。
- **蒙特卡洛树搜索（MCTS）作为互补思路**：Expectimax 对随机落子**穷举**所有新方块、按概率求精确期望（树是确定性的）；MCTS 则在每个模拟里**采样**生成新方块、用大量随机模拟去估计每个走法的期望价值（树是采样驱动的），选择阶段用 UCB1 平衡「利用 / 探索」。两者都建立在不可变棋盘上、共享同一套启发式。MCTS 的强度随 `--iterations` 提升而提升，本项目的实现把落子的随机性折叠进树的边上（只展开我方决策点），模拟阶段用「得分 + 启发式」的贪心默认策略走到死局。

## 扩展方式

- **加策略**：在 `strategy/` 新建一个文件，继承 `Strategy`、加 `@register`，在 `strategy/__init__.py` 里 import 一次即可。CLI 的 `--strategy` 选项由注册表自动生成，不用改编排层和入口。
- **换界面**：实现 `Renderer` 的 `frame()`（`start()`/`finish()` 可选），传给 `GameRunner` 即可，core 与 strategy 完全不受影响。

## 测试

`tests/` 共 140 个用例，stdlib `unittest`，无第三方依赖：

| 文件 | 覆盖 |
| --- | --- |
| `test_board.py` | 构造校验、不可变性、变换的对合性 |
| `test_rules.py` | 合并语义边界、四方向坐标变换、纯函数性 |
| `test_game.py` | 种子可复现、移动与生成解耦、快照隔离 |
| `test_strategy.py` | 策略通用契约、注册表、启发式各维度 |
| `test_render.py` | 版面逐行断言、输出流可注入 |
| `test_runner.py` | 四种终止原因、装配、批量跑分、greedy 显著优于 fixed |
| `test_parity.py` | **与拆分前实现的等价性对拍** |

`test_parity.py` 里内嵌了从原 `2048.py` 逐行转写的参考实现，对 3000 个随机棋面 × 4 个方向逐一比对棋面、得分、`moved` 标志，另对 2000 个棋面比对 `game_over`——用来证明拆分只改结构、没改语义。
